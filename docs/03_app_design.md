# 원클릭 층 전환 앱 설계안

- 작성일: 2026-10-13
- 근거: [01 로봇 조사](01_robot_investigation.md), [02 청소 앱 내부 분석](02_clean_app_internals.md)
- 상태: 설계 초안. 02 문서 5장의 확인 사항이 통과해야 확정된다.

## 1. 목표

층을 손으로 옮긴 뒤 사용자가 하는 일을 **"스티커 위에 로봇을 놓고 층 버튼 한 번"** 으로 줄인다.

| | 지금 | 목표 |
|---|---|---|
| 조작 | 지도 관리 앱 실행 → 층 변경 → 청소 앱 실행 → 로컬라이즈 → 청소 시작 | 층 버튼 1회 |

## 2. 방식

Keenon 에 원래 있는 **지표점(landmark) 위치 지정** 기능을 그대로 쓴다.

1. **준비(1회)**: 각 층 시작 위치 바닥에 스티커를 붙이고, 지도 관리 앱에서 그 자리에 지표점을 등록한다. 좌표는 ROS 가 보관한다.
2. **사용**: 로봇을 스티커에 맞춰 놓고 새 앱에서 층을 누른다.
3. 새 앱이 ROS 에 "이 지표점 위치에 있다"고 알린다 → ROS 가 층과 위치를 확정한다 → 청소 앱은 지도를 자동으로 따라 바꾼다 → 새 앱이 확인 후 청소를 시작한다.

새 앱은 좌표를 직접 다루지 않고 **층 ↔ 지표점 id 대응만** 가진다.

## 3. 구성

```
┌──────────────── 새 앱 (Android, 태블릿에 설치) ────────────────┐
│  화면          층 버튼 · 진행 단계 · 실패 사유                  │
│  시퀀서        단계 실행, 제한 시간, 실패 시 중단               │
│  층 프로필     층 → 지표점 id, 시작할 청소 작업                 │
│  로봇 게이트웨이                                               │
│    ├ CoAP 클라이언트 → 192.168.64.20:5683 (위치 지정·상태)      │
│    └ HTTP 클라이언트 → localhost:8089 (청소 앱: 지도·작업)      │
│  기록          단계별 요청/응답 로그                           │
└───────────────────────────────────────────────────────────────┘
```

| 구성 요소 | 책임 |
|---|---|
| 화면 | 층 목록(`/mapFloorList` + 지표점 유무), 실행 확인 창, 단계 진행 표시 |
| 시퀀서 | 아래 4장의 단계를 순서대로 실행하는 상태 기계 |
| 층 프로필 | `GET /navigation/dest_posesV2` 에서 `landmark` 지점을 층별로 읽어 자동 구성. 층에 지표점이 여러 개면 사용자가 기본값 지정 |
| 게이트웨이 | 위치 지정 방법을 인터페이스로 분리 (지표점 / 좌표 직접 / 태그) |
| 기록 | 문제 추적용 |

기술: Kotlin, Android 10(API 29), 32비트 ARM, CoAP 는 Californium, HTTP 는 OkHttp.

## 4. 시퀀스

| 단계 | 동작 | 통과 조건 | 실패 시 |
|---|---|---|---|
| 0 사전 점검 | `/clean/status`, `/task/status`, `/charge/status`, `/position/robotPosInfo` 조회 | 정지, 작업 없음, 충전기 위 아님, 목표 층에 지표점 있음 | 시작 안 함, 사유 표시 |
| 1 확인 | "N층으로 전환합니다" 창 | 사용자 확인 | 취소 |
| 2 위치 지정 | `POST /clean/relocationPosition {"action":3,"id":<지표점 id>}` | 응답 `code 0` | `/position/relocationPosition` 로 1회 재시도 후 중단 |
| 3 인식 확인 | `/position/status` 관찰 (제한 시간 약 60초) | `status 0`, `floor == 목표 층`, `type 11`, `poseId == id`, 좌표가 지표점 근처 | 중단. 청소 시작 안 함 |
| 4 지도 동기 확인 | `GET :8089/getCurrentLoadMapInfo` | 청소 앱의 지도가 목표 층 | `POST :8089/robotLoadMapOpenPosition {"mapId"}` 로 맞춘 뒤 재확인 |
| 5 청소 시작 | 1차: 청소 앱 화면을 띄움 / 2차: 작업 자동 시작 | — | 사유 표시 |

안전 원칙

- 3단계가 통과하지 않으면 **절대 청소를 시작하지 않는다.** 잘못된 층·위치로 주행하면 충돌 위험이 있다.
- **2·3·4층은 같은 지도**라 로봇이 센서로 구분하지 못한다. 사용자가 누른 층이 유일한 근거이므로 1단계 확인 창은 생략하지 않는다.
- `/restartRosNode`, `/devices/reboot`, 지도 다운로드 계열 API 는 사용하지 않는다.

## 5. 단계별 개발 계획

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| A 검증 | 한 층에 지표점을 등록하고, 청소 앱의 기존 "위치 선택" 화면으로 위치 지정이 되는지 확인. 그 순간의 로그 캡처 | `action 3` 요청·응답과 소요 시간 확보 |
| B 읽기 전용 앱 | 층 목록, 지표점 목록, 현재 층·좌표·인식 상태 표시 | 청소 앱과 동시에 통신해도 문제없음 |
| C 위치 지정 | 2~4단계 구현 (청소 시작 제외) | 층을 옮겨 가며 반복 성공 |
| D 청소 연결 | 5단계. 먼저 청소 앱 화면 띄우기, 이후 자동 시작 | 원클릭 완성 |
| E 태그 | 필요 시 | 아래 6장 |

A 단계 결과 지표점만으로 충분하면, 새 앱 없이 **청소 앱의 기존 위치 선택 화면만으로도 절차가 꽤 줄어든다.** 그 경우에도 새 앱은 "버튼 한 번 + 확인 + 청소 시작 자동화"를 더한다.

## 6. AprilTag / QR (2단계 과제)

- 태블릿에 카메라가 없다. USB 카메라를 태블릿에 추가하는 방법이 현실적이다.
- 태그의 역할은 **층 식별의 자동화**다(특히 같은 지도를 쓰는 2·3·4층). 태그 id → 지표점 id 로 연결하면 4장의 시퀀스를 그대로 쓴다.
- Keenon 자체에 라벨 기반 초기 위치 인식(`RosLocationType 6`, ROS `label` 테이블)이 있으므로, 직접 구현 전에 이 기능의 사용 가능 여부를 먼저 확인한다.

## 7. 전제 조건

- 2~4층에는 청소 구역이 없다. 청소를 시작하려면 먼저 구역을 만들어야 한다.
- 지표점 등록은 지도 관리 앱에서 사람이 한 번 해 줘야 한다.
- 태블릿에 앱 설치는 `adb install` 로 한다(루트 가능, userdebug).
